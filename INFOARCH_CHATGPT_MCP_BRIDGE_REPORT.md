# ChatGPT delegation MCP bridge — 2026-10-30

This optional local stdio server exposes `submit_delegation` and `get_delegation_status` over MCP and forwards to the existing canonical Kanban delegation API. It adds no scheduler or database and does not itself run work. The Worker and Kanban API must already be available and configured separately. The earlier isolated real-model Worker evidence is recorded in `INFOARCH_REAL_MODEL_E2E_20261030.md`; it is not evidence of this MCP bridge's end-to-end deployment.

## Local operation

Run `scripts/kanban_chatgpt_mcp.py` with a Python environment containing the project's optional MCP dependency (`mcp==2.3.0`). An MCP stdio host launches it using its Python interpreter and absolute script path. Set `HERMES_BASE_URL` and `HERMES_DASHBOARD_SESSION_TOKEN` (or `HERMES_SESSION_TOKEN`) in the server process environment using the host's secure secret facility. Do not put tokens in arguments, tool inputs, transcripts, source control, or logs. Configure a trusted HTTPS API endpoint, or HTTP only for loopback. Redirects are rejected; do not put credentials, a query or a fragment in the base URL. The adapter does not provide a URL argument to tools. Restrict access to the launch environment and use a dedicated least-privilege credential where the backend supports one; the existing dashboard session token may be broader than these two operations.

The caller must provide an explicit board and stable UUID before submission and retain them with the exact title, body and assignee. `origin` is fixed to `chatgpt`. Retries with the same board, UUID and payload return the existing receipt; changing the payload for a UUID on that board is rejected by the canonical API (HTTP 409). The same UUID on a different board is a different receipt, so never change boards on retry. After a timeout or lost response, query status with the original board and UUID and, if necessary, retry the exact original payload. A 410 means the original task is missing; it is not permission to silently create a replacement. The adapter sets a 20-second network timeout, bounds input lengths, does not return upstream error bodies, and does not follow redirects. Results and task content are untrusted; host-side approval and prompt-injection controls remain necessary.

## Scope and remaining acceptance

The MCP annotations describe submission as a write, idempotent only under the stated replay contract, and status as read-only. They are hints, not authorization. Any host must enforce user intent, caller identity, board and action authorization, rate limits, secure credential storage and transport, and auditability. The shared session token does not itself establish per-user or per-board least privilege. Protect any task results returned to the host.

This is a local stdio adapter and is not a hosted MCP endpoint, ChatGPT connector registration, OAuth integration, MCP Events implementation, or production-ready deployment. A supported remote transport and authenticated, authorized service boundary would need separate design and verification before hosted ChatGPT/Work use; do not expose this process directly to the internet. Registration, product compatibility, actual ChatGPT invocation, production deployment and end-to-end action approval remain unverified. No production Gateway, Proxmox, Flip7 or Mobile worktree changes were made for this bridge.
